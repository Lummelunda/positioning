# Scaleout offer framing: two buyer entry points

**Status:** Working hypothesis from the positioning discussion, 27 September 2026. This is a proposed way to structure the offer. It is not a verified statement about what Scaleout can deliver independently today or how buyers actually purchase it.

## Start with the buyer's need

The starting point is the buyer's operational task or capability need. Some buyers need an AI function for a mission task; others already have models and need to operate and improve them. These needs can occur together.

| Entry point | Buyer's question | Relevant Scaleout offer |
|---|---|---|
| **Mission application** | What will the AI do in our operation? | A defined workflow, currently exemplified by tactical computer vision. |
| **Model operations** | How will we deploy, evaluate, control and improve AI across equipment and sites? | Scaleout Edge, potentially using the buyer's existing models. |

This suggests three possible buying scopes: **an application evaluation, a model-operations evaluation, or a combined deployment**. Each scope needs a clear deliverable, integration boundary and evidence. These are proposed scopes, not confirmed standalone products.

## Where federated learning fits

Federated learning is an important Scaleout capability, particularly when useful data is held at separate sites and cannot be pooled. It should not be a requirement Scaleout imposes on every buyer. A buyer may need a visual function, local model evaluation, or controlled deployment and updates without needing cross-site learning.

The buyer-facing path is:

**Operational task → application or model-operations need → operating constraints → relevant Scaleout scope → evidence**

For a buyer specifically seeking distributed learning without pooling data, that capability can be the entry point instead. Cross-site coordination and federated learning are related but not identical; the latter is one technical approach to learning across separate data holders.

## The product question behind the positioning

**Can Scaleout deliver and support each narrower scope without requiring the full cross-site learning workflow?** If yes, separate entry points may widen the range of relevant buyer conversations. If no, describe the offer as a combined scope rather than implying independently available products. In either case, claims about a mission application need evidence for the mission function itself; a strong learning architecture does not substitute for that evidence.

A concise offer principle is:

> A defined mission function, with a clear path to local and cross-site improvement when needed.

The purpose of this structure is to let buyers first recognise what Scaleout can do for their requirement. Federated learning then strengthens the case where the buyer's data and operating conditions make it valuable.

## Questions to resolve internally

1. Which mission application workflows can be evaluated and delivered without cross-site learning?
2. Which model-operations capabilities can be delivered for a single site or an existing customer application?
3. What is the baseline deliverable, and what requires customer-specific engineering, hardware or accreditation?
4. What evidence supports each scope independently, and what evidence supports the combined offer?
5. Which buyer situations actually arise often enough to justify distinct offers or messages?
